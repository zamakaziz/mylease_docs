MyLeaseAudit Notes & Discussions Enhancement
Recommendation for UI/UX Designers and Developers
1. Executive Summary
MyLeaseAudit already has a Notes concept, but the needed functionality is broader than simple
note-taking. The recommended solution is to enhance Notes into contextual Notes &
Discussions.
This should not be a Slack-style chat system and should not be a separate chat module. Instead,
discussions should be attached directly to the audit item being discussed.
Recommended name:
Notes & Discussions
Purpose:
Allow users to ask questions, comment, tag specific users, receive notifications, attach support,
record decisions, and resolve discussions directly within the audit context.

2. Product Principle
The discussion should stay attached to the work item.
Users should be able to discuss:
Audit
Document
Validation Finding
Finding / Observation
Checklist Item
Approval Request
Savings Record
Generated Report
without leaving the current screen.

3. Problem Being Solved
Current-style notes are usually passive.
They answer:
What did someone write down?

MyLeaseAudit Notes & Discussions Enhancement
The enhanced Notes & Discussions feature should answer:
Who asked the question?
Who was asked?
Who responded?
What was decided?
Was the issue resolved?
Where is the discussion attached?
Was the notified user alerted?

4. Recommended UX Approach
4.1 Do Not Build Full Slack
Do not build:
Channels
Open chat rooms
Team-wide feeds
General chat
Real-time social chat
That would create unnecessary complexity.
4.2 Build Contextual Discussion Threads
Build:
Object-level discussion threads
Threaded replies
@mentions
Email notifications
In-app notifications
Attachments
Open / Resolved status

Search

23. Notification Workflow

MyLeaseAudit Notes & Discussions Enhancement
1. User creates message.
2. System parses message for @mentions.
3. System creates DiscussionMention records.
4. System creates in-app notifications.
5. System sends email notification to mentioned users.
6. Mentioned user opens discussion from email or dashboard.
7. Mentioned user replies.
8. Original commenter receives reply notification.
9. If resolved, system updates thread/message status.
10. Activity log records the event.

24. Resolution Workflow
1. Auditor asks a question in a discussion.
2. Auditor mentions a user.
3. Mentioned user receives email and in-app notification.
4. Mentioned user replies.
5. Auditor or QC marks the question Answered or Resolved.
6. If all open questions are resolved, thread status may become Resolved.
7. Project Manager/Admin may close the thread.

27. Final Recommendation
Implement Enhanced Notes & Discussions as a contextual collaboration layer.
It should:
Enhance existing Notes
Attach discussions to audit objects
Support threaded messages
Support @mentions
Notify users by email and in-app notification
Support attachments
Support open/resolved workflow
Log activity
Remain searchable
This is the simplest effective solution because it avoids building a separate Slack-style system
while giving auditors, QC reviewers, project managers, and administrators the collaboration
features needed to resolve audit questions and document decisions directly inside MyLeaseAudit.
